# IT Project Governance Dashboard

## 1. Dashboard Purpose

This dashboard provides a consolidated view of project schedule,
budget, delivery progress, risks, issues, and testing status.

The dashboard is designed for project managers, PMO teams,
technology leads, and executive stakeholders.

All project information and metrics are fictional and intended
for portfolio demonstration purposes.

## 4. Delivery Performance

Project progress is reviewed weekly against the approved baseline.

Key monitoring activities:

- Compare planned and actual completion.
- Identify schedule slippage and milestone dependencies.
- Review budget consumption against the approved plan.
- Escalate material deviations to project stakeholders.

Refer to sample-kpi-data.csv for the illustrative weekly dataset.

## 6. Escalation Criteria

The following thresholds are illustrative and would be agreed
with stakeholders during project initiation.

- Schedule variance exceeding 10%: Escalate to the project sponsor.
- Budget variance exceeding 10%: Initiate financial review.
- Critical defect identified: Escalate to the release decision team.
- High-impact risk materializes: Activate the mitigation plan.

## 7. Reporting Limitations

This is a documentation-based dashboard mockup.

The figures are simulated. They are not connected to a live
reporting platform or actual banking systems.

This case study demonstrates project governance and reporting
concepts, not an actual client engagement.
